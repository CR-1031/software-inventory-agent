# Требования к проекту (FURPS+)

## Агент инвентаризации программного обеспечения

---

### F — Функциональные требования (Functionality)

| ID | Требование |
|----|-----------|
| F1 | Агент должен сканировать список установленного ПО через реестр Windows (HKLM\Software\Microsoft\Windows\CurrentVersion\Uninstall) |
| F2 | Агент должен сканировать 32-битные приложения на 64-битных системах (HKLM\Software\WOW6432Node\...) |
| F3 | Агент должен собирать следующую информацию о каждом приложении: название, версия, издатель, дата установки |
| F4 | Агент должен формировать отчет в формате JSON |
| F5 | Агент должен поддерживать сохранение отчета в файл |
| F6 | Агент должен поддерживать отправку отчета на удаленный сервер по HTTP |
| F7 | Агент должен работать через интерфейс командной строки (CLI) |
| F8 | Агент должен вести логирование всех операций и ошибок |

---

### U — Требования к удобству использования (Usability)

| ID | Требование |
|----|-----------|
| U1 | Агент не требует графического интерфейса и работает в фоновом режиме |
| U2 | Конфигурация осуществляется через простой JSON-файл |
| U3 | Агент должен иметь понятную справку по командам (--help) |
| U4 | Сообщения об ошибках должны быть понятными и информативными |

---

### R — Требования к надежности (Reliability)

| ID | Требование |
|----|-----------|
| R1 | Агент должен корректно обрабатывать отсутствие прав доступа к реестру |
| R2 | При ошибке чтения одного приложения агент должен продолжать сканирование остальных |
| R3 | Агент должен корректно завершать работу при любых сбоях |
| R4 | Логи должны сохраняться для анализа ошибок |

---

### P — Требования к производительности (Performance)

| ID | Требование | Значение |
|----|-----------|----------|
| P1 | Время сканирования | Не более 30 секунд |
| P2 | Потребление оперативной памяти | Не более 50 МБ |
| P3 | Нагрузка на процессор | Не более 5% в фоновом режиме |
| P4 | Размер исполняемого файла | Не более 10 МБ |

---

### S — Требования к поддерживаемости (Supportability)

| ID | Требование |
|----|-----------|
| S1 | Язык реализации: Python 3.8 или выше |
| S2 | Код должен быть документирован (комментарии, docstrings) |
| S3 | Должна быть документация по установке и использованию |
| S4 | Использование системы контроля версий Git |
| S5 | Наличие unit-тестов для основных функций |

---

### + — Дополнительные ограничения и требования

| ID | Требование |
|----|-----------|
| +1 | Поддержка операционных систем: Windows 10/11 (64-bit) |
| +2 | Агент не должен требовать прав администратора |
| +3 | Отчет должен содержать дату сканирования и имя компьютера |
| +4 | Возможность расширения для сбора информации об оборудовании (опционально) |
| +5 | Открытый исходный код (без лицензионных ограничений) |

## Приоритеты требований

| Приоритет | Описание | Требования |
|-----------|----------|------------|
| **Высокий** | Обязательны к реализации | F1, F3, F4, F7, P1, P2, S1, S4 |
| **Средний** | Желательны к реализации | F2, F5, F8, U1, U2, R1, R2 |
| **Низкий** | Опциональны | F6, U4, +4 |

---

## Стейкхолдеры

| Стейкхолдер | Интересы |
|-------------|---------|
| **Системный администратор** | Получение актуального списка ПО на всех ПК, контроль лицензий |
| **Руководитель IT-отдела** | Оценка лицензионной чистоты, планирование бюджета |
| **Пользователь ПК** | Агент не должен мешать работе и потреблять много ресурсов |
| **Разработчик (студент)** | Реализация проекта с использованием современных технологий |

---

## Анализ аналогов

| Аналог | Сильные стороны | Слабые стороны |
|--------|----------------|----------------|
| **GLPI + FusionInventory** | Бесплатный, мощный отчетный механизм | Сложная настройка |
| **ManageEngine Desktop Central** | Богатый функционал, удобный UI | Платная, тяжелая |
| **PowerShell Get-WmiObject** | Встроенный инструмент | Нет централизованного сбора |
| **Belarc Advisor** | Детальные отчеты | Не автоматизирован для многих ПК |

**Вывод:** Разрабатываем легковесного агента на Python с выгрузкой в JSON для дальнейшей интеграции.
